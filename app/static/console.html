Prove it never posts twice

Networks drop, people double-click, clients retry. Every post above was sent with an Idempotency-Key, so sending the same request again returns the first answer instead of posting again.

Publish first, then try these.

Every change carries an Idempotency-Key

Each request that changes something (upload, check, publish, live test) is sent with a unique key. The same key protects the post at three levels:

  1. API: the same key with the same content returns the stored first answer, marked Idempotent-Replayed: true. The same key with different content is refused (409).
  2. Platform: a fingerprint of the key goes inside the post (ltn-…), so after a lost response the service finds the post it already made instead of posting again. Partner sites receive the key itself.
  3. Ledger: a post already recorded as published for that key is returned, never sent again.
